# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`orochi` is a single Rust binary: an adaptive scheduler that picks an **agent × model × reasoning level × session strategy** for a coding task, drives the chosen CLI agent over ACP (Agent Client Protocol) v1 stdio, evaluates the result locally, and learns from the recorded outcome. It can also expose *itself* as an ACP agent (`orochi serve`).

Rust 1.96.0 is pinned in `rust-toolchain.toml`; edition 2024. `Cargo.lock` is committed and every command uses `--locked`.

## Commands

```sh
cargo build --locked                       # debug binary (examples/demo.py expects target/debug/orochi)
cargo build --release --locked
cargo fmt --all -- --check
cargo clippy --locked --all-targets -- -D warnings   # warnings are errors in CI
cargo test --locked                        # requires python3 on PATH
```

Tests live only in `tests/*.rs` (no `#[cfg(test)]` modules in `src/`), so target them per file/name:

```sh
cargo test --test cli_e2e
cargo test --test adaptive ewma_reacts_to_recent_drift_and_scales_token_cost_to_task_size
python3 -m unittest discover -s tests -p test_quota_terminal.py   # also run by tests/adaptive.rs
```

End-to-end smoke without any account: `cargo build --locked && python3 examples/demo.py`.

CI (`.github/workflows/ci.yml`) runs fmt / clippy / test on ubuntu + macOS with Python 3 installed. No account, network LLM call, or API billing is needed for any test.

## Execution pipeline

`cli::execute` → `scheduler::run_with_events` is the spine; read those two in order before changing behavior.

1. **Quota refresh** (optional, `quota.refresh_before_run`) — `quota_sources::refresh` shells out to read-only native CLI probes (`codex app-server`, Claude/Antigravity `/usage` via the embedded `src/quota_terminal.py` PTY reader) and persists snapshots.
2. **Profile** — `router::profiler::profile` turns the raw task string + repo into a `TaskDescriptor` (task type, language, complexity, scope, ambiguity, capability needs). Purely local heuristics: keyword matching, so a request phrased outside its vocabulary lands on `implementation`/`Normal`. `router::classifier::refine` then asks an ACP agent to classify the task itself and merges the reply in one direction only — it may raise complexity and add a capability need, never lower or clear one. It runs **by default** (`classifier.enabled`), without `agent` trying every enabled, non-`routing_only` agent in configured order within one agent's worth of time, because sending the request to an agent that would run the work anyway puts the text where it was already going. Any failure keeps the heuristic; a cached reply (salted hash of the task) skips the call. Nothing that has no choice left to make may start an agent to ask: a dry run, a read-only seat, and a route pinned to both an agent and a model all keep the heuristic label.
3. **Discover** — `discovery::inspect`/`prepare` resolve each configured agent to a launch command (native CLI, existing ACP command, or an auto-installed adapter under `<data>/adapters/`), then `acp::Client::start_with_model` connects, creates a throwaway session and enumerates models/reasoning/modes. Runs up to 4 agents concurrently.
4. **Score** — `router::scorer::candidates` expands every (agent, model, reasoning, mode) tuple, applies provider policy + hard constraints + quota availability + `scheduler.required_success`, and sorts by `expected_cost`.
5. **Advise** (optional) — `router::advisory::advise` may consult a router, a frontier "judge", or a 2-round council. Every adviser is an `[[agents]]` entry (optionally `routing_only`) driven over ACP by `router::adviser::Session`: fresh session in an empty temp dir, permissions denied, council round two reusing the seat's session; without `model`, the adviser model is scored from the agent's models by policy at a per-role difficulty (router simple, council normal, frontier complex). Adviser rate/auth/unavailable failures update that agent's runtime cooldown. Its pick only *reorders* candidates that already passed every constraint.
6. **Select** — `learning::select` applies the EWMA/bandit strategy over the surviving list.
7. **Execute** — `acp::Client::configure` + `prompt`, streaming assistant output to stdout and routing/diagnostics to stderr.
8. **Evaluate** — `evaluator::evaluate` runs auto-detected or configured checks (`CI=true`, no stdin) and `evaluator::outcome` labels the run.
9. **Record** — `storage::Store` writes a `RunRecord` to SQLite; failures update `RuntimeState` cooldowns and the loop retries with a fresh `TaskEnvelope` up to `scheduler.max_attempts`.

`gateway.rs` (`orochi serve`), `chat.rs` (`orochi` on a terminal / `orochi chat`) and `collaboration/` (`orochi collaborate`, independent ACP sessions in copied workspaces) all re-enter this same scheduler rather than duplicating routing logic.

Non-obvious module notes:

- `types.rs` holds every cross-module struct. `RunRecord` is stored in SQLite as a JSON blob, so records written by older versions must still deserialize — new optional fields need `#[serde(default)]`.
- `acp.rs` is the only place that speaks the protocol. ACP configuration is **model-dependent**: `discover()` re-reads the `thought_level`/`mode` selectors *after* switching to each model, and supports both modern `configOptions` selectors and the legacy `models` / `session/set_model` shape.
- `chat/` decides how much machinery a message needs: `Session::steps` profiles it and splits complex or architectural work into design → implement (→ review) phases, each routed on its own in its own session and peer, handing its reply on; a failed implementation adds a review, and only a review answering `VERDICT: fix` adds one more pass. A message needing a capability (`image`, `browser`, `web`) the conversation's agent lacks runs as a one-off guest turn on a capable agent (clearing `--agent`), and the conversation keeps its own agent, told afterwards what happened. `scorer` also prices an agent another peer is running 1.4× higher (`ScoringContext::busy` from `mailbox::busy_agents`), so concurrent runs spread over accounts instead of racing for one.
- `chat/term.rs` owns the one screen the pinned input and the transcript share: transcript text is written at a tracked (row, column) above the input, so anything that changes the pinned height must free (and clear) the rows it no longer covers and scroll the transcript when it grows — and nothing may write into a half-written row. `tests/test_chat_terminal.py` (driven from `tests/cli_e2e.rs`, rendering the pty output through `tests/screen.py`) is the only test that can see those mistakes.
- `chat/mod.rs` classifies each turn **once** (`Session::profile`) and that one descriptor decides the escalation, the phase split and the routing — it travels into the scheduler as `RunOptions::descriptor` so the scheduler does not ask again about text the console rewrote, and a read-only seat never classifies the prompt Orochi wrote for it. When the derived team splits the work (`Plan::splits_work`, i.e. more than one implementer) the console offers to run the collaboration instead of the turn, and only on a terminal: it is the one escalation that starts several agents at once and writes back, so it is the one thing that asks first. Typing `/` lists matching commands above the input, Up/Down select and Tab/Enter take one.
- `chat/`: `mod.rs` is the session (key loop, queued messages, commands, approval modes, the mailbox `Feed` and the per-turn `Screen`); `term.rs` owns the terminal — raw-mode key decoding, the pinned input line with its attachment rows and status row (a DECSTBM scroll region keeps the transcript in the terminal's own scrollback), and the restore on exit. Each message is one `scheduler::run_turn` with `RunOptions.interactive`, which keeps the scheduler off stderr and reports `acp::Progress` events instead (route, unavailable agents, checks, attempt results; `acp.rs` adds tool calls with their `rawInput` detail and diffs, plans and thinking), sends the text as typed on the first attempt, skips evaluation when `context::tree_fingerprint` is unchanged, and never retries a turn the agent finished. Keys typed during a turn edit the same input line: Enter queues the message, Esc raises SIGINT, Shift-Tab cycles the agent's own session modes (`Continuation::modes`) or Orochi's ask/always/never. Attachments (`types::Attachment`) come from pasted paths and `@path`, and `acp::Client::prompt_with` sends images inline, text as embedded resources, and anything else as a resource link, honoring the agent's prompt capabilities. `run_turn` reports the recorded session (`Continuation`); later messages pin that agent/model and pass `resume` when the agent advertised `session/load`, otherwise a bounded in-memory transcript goes into the task text; history and transcripts stay in memory only.
- `router/classifier.rs`: reuses `adviser::Session` (fresh session, empty temp dir, permissions denied) at `Complexity::Simple`, so the cheapest model clearing the policy floor is picked. A reply naming a label outside `classifier::TASK_TYPES` is discarded rather than stored — an invented label would silently split the `storage::history` strata an agent/model's EWMA is keyed by. Raising complexity is not free downstream: `roles::seats` seats a second read-only agent for `Complex`/`Extreme` or structural work, so an enabled classifier can double what a chat turn costs.
- `learning.tier_pooling` (off by default) starts a model with no history of its own from what other models of the same provider and policy tier did on the same task type, complexity, reasoning and mode (`storage::tier_runs`, `learning::estimate_evidence`). Tier is derived from the model ID at read time, so no stored record changes; `unknown` is never pooled. Replay reads tiers from the bundled policy, not the installed one, so a replay result does not move when policies are updated.
- `benchmark.rs` (`orochi benchmark`, `benchmark-tune`) replays paired measured outcomes offline; it never contacts an agent and never writes to the operational DB.
- `process.rs`: every ACP agent is launched as `orochi --internal-supervise <lease> <cmd>…` (dispatched in `main.rs` before clap). The supervisor leads the process group, records the agent and observed descendants as (pid, start time) leases under `<data>/processes/`, and kills them if its owner dies; `cli::execute` enables this and reaps leases whose owner is gone. Library callers that never call `process::enable` (e.g. `tests/adaptive.rs`) spawn agents directly.
- `memory.rs` is captured with no call of its own: the classifier already reads every request, and its reply may carry up to two `remember` items (repo scope unless the user says it holds for every project), each shown as one `remembered:` line when kept. The note opens every **fresh** agent session — `scheduler` where the prompt is finalised (so chat, one-shot, seats and `serve`), and `collaboration/turn.rs` for participants — and is skipped on `resume`, since that session heard it when it began. Items Orochi wrote carry `<!-- auto seen:N last:T -->`; heard once they expire after 90 days, twice or more after 180, and the user's own unmarked lines never expire, are never replaced and are injected first. Budgets: `memory.user_chars` 1500, `memory.repo_chars` 2500. A console session with two or more messages is looked back over once at its end (`classifier::distill`, Esc skips): only what the user said, kept in memory across `/new` in `chat::Session::said`, never the agents' replies. The classifier also reads, from what is remembered, which agent or model the user wants for this kind of work and returns it as `prefer` — a name fragment of `[a-z0-9._-]`, at most 64 characters, so it cannot carry the user's words into the classification cache (whose key includes the memory listing). `scorer` multiplies a matching candidate's cost by 0.8 after every gate; it never brings a gated candidate back. Designed in `docs/personalization-design.md`.
- `mailbox::prompt_note_for` asks peers to claim a named part of the work with `set_status` *before* changing anything and to leave what others claimed alone, and to hand what a peer is waiting on (a decision they will build on, an interface they will call) over as soon as it holds rather than at the end. It only matters between separate Orochi processes: the repository lock is exclusive unless `scheduler.shared_workspace` is set, and a chat's second seat cannot write at all.
- `mailbox.rs`: one peer per **agent session** (normal runs, `collaborate` and chat phases, not `serve`), so agents inside one process reach each other too; `mailbox::join` only activates the process and `register_session` names each session (`--peer-name` is the prefix). Peers are scoped to the repository's git common dir so worktrees share a channel. `acp.rs` attaches `orochi --internal-mailbox …` (a hand-rolled stdio MCP server, dispatched in `main.rs`) to every non-adviser `session/new`; the scheduler and collaboration prompts prepend `mailbox::prompt_note()`. Messages live in `<data>/mailbox.sqlite3` with a retention window, never in telemetry. `scheduler.shared_workspace` turns the repository lock into a shared lock; applying a collaboration result stays exclusive. `busy_agents(except)` counts every seat but the named one — including this process's own other seats — so the scorer steers them to different accounts.
- `router/roles.rs` + `chat/mod.rs`: a chat turn derives its seats from the task rather than from a fixed pairing. Structural, long-horizon or complex work seats a second, read-only agent beside the one doing it; a request that asks the agents to work together seats as many as it asks for (`TaskDescriptor::seats`, capped by `roles::MAX_SEATS`), each a different perspective from `roles::PANEL`, and a request that only asks them to talk (`task_type == "discussion"`) seats nobody who may write. Every seat runs concurrently under the one workspace lock, in the user's own tree, and they talk over the mailbox. The second seat runs with `RunOptions { read_only: true, verify: false }` — `acp.rs` refuses it every permission request whose `toolCall.kind` is not read/search/fetch/think, and only the lead's turn runs the evaluator. Its own output stays out of the transcript; what it has to say reaches the user as mailbox messages.
- `collaboration/plan.rs`: derives the team from the `TaskDescriptor` when `collaborate` is given no `--plan`, so the deep path stops needing a hand-written one. Counts come from complexity and whether the work is structural; implementers are additionally capped by the number of separate top-level areas the task touches (its `candidate_files`, or the repository's own directories when it named none) — a second implementer inside one directory races the first rather than halving the work. `--dry-run` prints the derived plan as a plan file, so it can be saved, edited and passed back to `--plan`.
- `collaboration/`: `mod.rs` holds the plan, the derived step list (turn groups, merge, discussion rounds, apply) and the resumable `report.json`; `turn.rs` builds prompts, parses trailing JSON (management state, `{"messages": …}`), and runs a turn group concurrently with per-member failover; `workspace.rs` copies, three-way merges (`git merge-file` outside any repo) and commits with stale-write checks; `apply.rs` merges parallel implementers and applies a verified result to the user's tree. Step numbering for single-implementer plans without discussion must stay identical to older reports.

## Invariants (tests assert these — don't regress them)

- **Memory is the user's text, so it lives beside telemetry, never in it, and only Orochi writes it.** `memory.rs` keeps `<data>/memory/USER.md` and `<data>/memory/repos/<repository_id>/MEMORY.md` as plain Markdown. A `MEMORY.md` inside the target repository is never read, no agent gets a tool that writes memory (agent output follows the repository's content), and routing advisers never see it — only the classifier is shown the current repository's listing, so it can say "again" instead of adding a duplicate. Its `remember` / `reinforce` / `replaces` fields are `skip_serializing`, so the classification cache still holds labels only. A repository's notes never reach another repository's prompts. Tests in `tests/core.rs` (`mod memory`) and `a_remembered_note_opens_each_fresh_session_once` pin all of this.
- **A classified failure reports its kind, not the text it was read from.** Bridges wrap provider errors in a generic `-32603`, and the nested `data.details` that `agents::classify_error` reads carries provider request IDs (`tests/adaptive.rs`, `nested_acp_rate_limit_details_are_classified_without_exposing_them`). Only an `ErrorKind::Other` — where the kind says nothing a user can act on — puts that cause in the message, on one line, capped, control characters gone and escapes made visible. `RunRecord` stores `kind.key()` and never the message.
- **Nothing sensitive is persisted or transmitted.** Task text, conversation, source, diffs, agent stderr and check output never reach SQLite. The router/judge/council payload is classification attributes + at most 12 opaque candidate summaries — no task text, filenames or repo paths (`tests/core.rs`, `router_payload_excludes_task_text_and_filenames`). The opt-in `[classifier]` is the **one** adviser shown the task text, because it cannot classify without it; it still persists nothing, keying its cache by a salted hash (`classifier_sees_the_task_but_caches_only_a_hash_of_it`). Repository identity is a salted hash. Agent-to-agent mailbox messages may contain task content, so they stay in the separate, time-limited `mailbox.sqlite3`.
- **`end_turn` alone is not success.** `Outcome::PartialSuccess` means unverified or diff-only; only real check passes yield `Success`. Partial, cancelled, rate-limited/auth/unavailable, and mid-run config-switch runs are excluded from learning labels (`learning::labeled`).
- **Usage is nullable, never zeroed or estimated.** `Usage::total()` must not double-count reasoning inside output or cache inside input.
- **`model == "*"` in `runtime` means agent/account-wide.** A rate limit without an explicit `data.scope = "model"` applies to the whole agent; model-scoped failures must not blanket-disable an agent.
- **A verified outcome is never relabeled; an unverified one is labeled only weakly, once.** `RunRecord::feedback` (what the user did next in the console: `continued` 0.2, `rerouted` 0.3 — uncalibrated heuristics; an interruption alone labels nothing, since stopping a turn may mean the user forgot to say something as easily as the agent went astray, and only `/reroute` after it counts against the route) is the only part of a record written after the run, via `Store::feedback`, first signal only, prediction untouched. `learning::label` uses it only for `PartialSuccess` and `Cancelled`; weight enters as `decay^w`, so weight 1 is the unweighted update. `calibrate` reports weak signals apart from the verified numbers. `/new`, quitting and messages queued while the agent was working are not verdicts.
- **Predictions are frozen before execution.** `RunRecord::prediction` is what calibration compares against; never rewrite it after the fact.
- **The target repository is never trusted.** Config is never auto-loaded from the repo; relative `PATH` entries are skipped when resolving executables; adapter installs are pinned-version, install-scripts-disabled, into Orochi's own cache.
- **`collaborate` leaves the user's working tree alone unless `--apply` is given, and applies only a result whose real checks passed.** Writes are staged and re-verified against the merge input; a tree edited during conflict resolution blocks instead of being overwritten.
- **Constraints bound every "smart" layer.** Router/judge/council/bandit may only choose among candidates that already passed quota, policy, capability and `required_success` gates, and are additionally capped by `max_cost_ratio` (1.25×) and a resource-fraction budget.

## Conventions

- Config structs use `#[serde(default, deny_unknown_fields)]`, so a new field needs a `Default` impl entry and usually a check in `Config::validate`. `orochi config show` redacts `agent.env` values.
- Code comments are English and rare — they exist to record a decision ("never auto-run a relative PATH entry…"), not to narrate. Match that density.
- `.orochi/` is gitignored local scratch (implementation backups, live-E2E artifacts, downloaded tooling) — not source; ignore it when searching.
- Exit codes: `0` completed, `1` execution/eval/config error, `2` CLI usage error, `130` interrupted or permission denied.

Path-scoped rules live in `.claude/rules/` and load when the matching files are opened: `tests.md` (test harness), `policies.md` (policy JSON + scoring), `docs.md` (Japanese user-facing docs).
